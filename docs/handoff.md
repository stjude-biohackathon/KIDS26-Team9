## What this document must contain

- **What we built** — one paragraph, honest about scope.
- **Main result** — what the app does, and what was verified about it. Reference the sign-off table
  from task **B-08**: which of the seven datasets were checked against the reference oracle, and
  whether every number matched.
- **How to run it** — from a clean clone. This must be the procedure actually used in the
  clean-clone test (**B-09** / **B-11**), not a reconstruction.
- **Repository map** — what lives where.
- **Data and source notes** — provenance and licence for every example dataset; the `cureAssess`
  package version vendored, its authors, and its upstream URL; the tutorial manuscript the workflow
  comes from.
- **Known limitations** — be specific and be honest. Expected to include at minimum: the published
  methods assess **one group at a time**, so there is no treatment-arm comparison; no covariate
  adjustment; mixture cure models only; the diagnostics are descriptive aids rather than a single
  decision rule; thresholds of 0.025 and 0.05 are conventions, not laws; local-only, not deployed.
- **What broke and what we would do differently** — the most useful section for whoever picks this up.
- **Next steps** — the stretch goals that did not land (**S-1** to **S-5**), in priority order, with
  a note on what each would cost. **S-1**, the follow-up truncation slider, should be first.
- **Open questions** — anything still marked `[to confirm]` across the documentation.

Also record where the demo materials live (deck, booth script, screenshots) so the next person can
reuse them.
