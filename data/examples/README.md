| File | Source | Derivation | Verified headline result |

## Provenance addendum — the four simulated scenarios are now committed CSVs

The three real datasets above are derived exactly as the table states. The simulated four are
not: the note above says they are "generated by committed code with a fixed seed rather than
stored as data", but the app's dataset registry (`CA_DATASETS` in `app/R/datasets.R`) loads every
built-in example from a CSV, so all four are now written to this directory as well. The generating
code is still committed and still the source of truth — the CSVs are its output, not a substitute
for it.

Regenerate every file in this directory, real and simulated, with:

```
Rscript data-raw/make_examples.R
```

That script verifies what it writes and fails loudly if a row count or the scenario-C/D
not-computable condition changes.

| File | Source | Derivation | Verified headline result |
| --- | --- | --- | --- |
| `sim_a.csv` | `simulate_cure_data()` | `n = 300`, `shape = 1.2`, `scale = 1`, `seed = 11`, `cure_fraction = 0.40`, `admin_followup = 10`, `dropout_rate = 0.03`; `time_scale = "none"` | **Cure model appropriate** |
| `sim_b.csv` | `simulate_cure_data()` | as above with `cure_fraction = 0.40`, `admin_followup = 1.5`, `dropout_rate = 0.03` | **Cure model not supported** |
| `sim_c.csv` | `simulate_cure_data()` | as above with `cure_fraction = 0.00`, `admin_followup = 10`, `dropout_rate = 0.03` | **Cure model not supported** — MZ, `qn` and Shen all `NA` |
| `sim_d.csv` | `simulate_cure_data()` | as above with `cure_fraction = 0.00`, `admin_followup = 10`, `dropout_rate = 0.45` | **Cure model not supported** — MZ, `qn` and Shen all `NA` |

`simulate_cure_data()` is the reference implementation in
[`docs/data-contract.md`](../../docs/data-contract.md) section 8, reproduced verbatim inside
`data-raw/make_examples.R`. It calls `set.seed()` itself, so each scenario is reproducible
independently of the order the four are generated in.

Two further differences from the data contract, both deliberate:

- **`.cured` is dropped before writing.** It is ground truth for verification only and must never
  be selectable as a status column, so it does not appear in any CSV.
- **The columns are `Y` and `D`.** The simulated frames are already in the package's own naming
  scheme and need no column mapping; the three real files keep their original column names so the
  mapper has something real to map.

The "Verified headline result" column is the `tests$receus$decision` string returned by
`cureAssess::cure.appropriateness(..., run_tests = "yes")`, confirmed by running all seven
datasets through the full pipeline. It is not the `final_recommendation` field, which reports the
Stage-1 AIC comparison instead.
